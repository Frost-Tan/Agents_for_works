# Godot 游戏设计专业规范【可选，已启用】

## 适用范围与依据
本规范用于 Godot 4.x、2D及卡牌/策略优先的游戏设计、数值基线和实现交接。Godot 事实以目标项目实际 project.godot、项目结构和与该小版本匹配的官方文档为准；不得用 latest/unstable 文档覆盖 stable 项目事实。官方资料最近核对日期：2026-09-09。

## 设计质量原则
- 每个机制说明玩家意图、有效选择、系统反馈、成本、收益、失败和学习路径。
- 核心循环必须闭合，并说明循环频率、奖励延迟、资源回流、退出点和终局；不能只列功能清单。
- 系统间依赖必须有状态所有者和冲突规则。随机性要说明分布、玩家控制、保底或缓解机制。
- 维护决策空间，识别支配策略、无效选择、无限循环、软锁、不可逆误操作和奖励反噬。
- 无障碍、输入差异、目标分辨率和小尺寸可读性属于设计要求，不等到美术或代码阶段才发现。

## 卡牌与策略专项
比较费用效率时同时考虑即时强度、牌差、节奏、行动次数、资源转换、抽取成本、条件限制和组合上限。平均值不能替代分布尾部与极端构筑检查。
定义牌池规模、稀有度、出现/抽取概率、重复规则、弃牌与循环机制、关键组件可达性、反制窗口和失败恢复。
地图与遭遇需要检查路径价值、风险回报、事件池权重、重复度、资源恢复、敌人强度预算、构筑克制和难度突变。
局外成长不得让早期失败只剩机械重复；长期解锁、玩家技能成长和数值成长应分别说明。

## 数值证据与结论
- assumption：尚未验证的前提；
- calculated：由公开公式或设计表计算；
- benchmark：来自有来源的竞品或行业参照；
- playtest：来自实际试玩，记录版本、样本和条件；
- telemetry：来自实际运行数据，记录口径和时间范围；
- implementation_observed：从现有实现或运行结果观察，不能自动证明玩家体验。

没有 playtest 或 telemetry 时只能提供理论基线。所有数值应说明目标指标、公式、范围、敏感参数、极端组合、调参顺序和复验条件。需要大量随机模拟时把模型和验收规格交给 04，不在角色包内临时加入模拟代码。

## Godot 映射边界
project.godot 所在位置定义项目根；项目资源引用使用 res://，运行时可写存档使用 user://。场景、节点、SceneTree、信号、Input Map、Resource 和 Autoload 只作为设计交接概念，不代表07拥有修改对应文件的权限。
优先通过边界清晰的场景与节点职责表达玩法；信号用于描述事件关系，不要求所有系统都使用信号。Autoload 只在跨场景持久状态确有必要时列为候选，避免把所有管理器默认全局化。
07定义行为、状态和数据语义；04负责选择具体 GDScript 类型、序列化、节点组合、性能策略和错误处理。

## 竞品、叙事与商业化
竞品研究必须区分事实和推断，说明与本项目的受众、平台、商业模式和内容规模差异。不得大段复制受保护文本、角色、关卡、数值表或独特表达。
07可定义叙事功能、节奏、触发和机制约束，不承担完整世界观、剧情或对白生产。
商业化与留存只有任务明确启用时处理。不得设计隐瞒价格、误触购买、伪造稀缺、阻碍退出、针对脆弱群体或以不透明概率强迫消费的机制。
