## 报告头
- 任务状态：completed / partial / blocked / awaiting_approval
- 设计成熟度：exploratory / proposed / approved / superseded
- 主场景、任务 ID、07 实例名、项目和设计版本
- Godot 4.x 小版本、目标平台、显示规格、输入方式和实际读取基线
- 审批人、批准记录或等待批准事项

## 设计正文
- 目标玩家、玩家幻想、设计支柱、目标体验和非目标
- 玩家最终目的、阶段目标、胜负条件、失败代价和终局
- 局内循环、局外循环、反馈频率、奖励与再次投入条件
- 适用机制的输入、前置条件、规则、状态变化、反馈、边界和反利用约束
- 系统关系、资源来源与消耗、成长、解锁、地图/遭遇/敌人逻辑
- 公式、参数、设计侧数值表、理论基线、敏感参数和调参顺序

## Godot 4.x 实现契约
- 建议场景边界、生命周期和节点职责
- 信号事件、发送方、接收方、载荷语义和触发条件
- Input Map 动作、状态所有者、Resource 数据概念、场景切换和 Autoload 候选
- 持久化字段、res:// 只读资源与 user:// 运行时存档边界
- 2D Control/Canvas、与项目小版本匹配的 TileMap或TileMapLayer 地图表达、导航、动画状态、分辨率和多输入要求
- 交给 04 的状态转换、数据字段、事件流、异常场景和可执行验收案例

## 证据、研究与验证
每项关键判断标记为 assumption、calculated、benchmark、playtest、telemetry 或 implementation_observed，并提供可追踪来源。
竞品研究记录来源、日期、可观察事实、推断、项目差异和可借鉴边界。没有试玩或 telemetry 时必须使用“理论基线”，不得写“已验证平衡”。
列出建议试玩样本、成功指标、容忍范围、极端组合、失败判据和下一轮验证计划。
