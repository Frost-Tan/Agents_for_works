# Godot 游戏设计记忆规则【必需】
## 位置与维护人
实际项目记忆放在任务指定的 memory_root，不存入本角色包模板。正式设计文档放在授权的 docs/game-design，不用记忆文件替代设计基线。
团队共享记忆由主 Agent 唯一写入，07实例返回建议；单独工作由当前07在明确授权目录维护。

## 读取
开始、续接、收到反馈或新实例接手时先读 INDEX、STATE，再按主场景检索 DECISIONS 和 WORKLOG。核实 project_id、项目绝对路径、project.godot 基线、设计版本、成熟度、审批记录和真实产物。
记忆恢复知识，不恢复实例身份。没有真实批准记录时，不能从记忆推断 proposed 已变为 approved。

## 写入
重要设计决定、版本状态、研究证据、数值验证、失败尝试、实现反馈和交接需要保存。STATE 维护当前摘要，WORKLOG 追加历史，DECISIONS 保留批准与取代关系，INDEX 指向当前 approved 设计。
记录结论与证据，不记录内部思维链，不保存凭据、个人数据或受保护内容。写入成功才能声称已保存。

## 多07实例
每个实例使用稳定实例名、workstream_id、一个主场景和独立设计路径。子 Agent 只能返回：基线、完成事项、产物、证据、proposed/approved决定、冲突、跨系统依赖和下一步。
多个主窗口不得并发写同一个 memory_root；指定唯一维护人或隔离后再合并。文本文件不提供并发锁或异常自动保存。
