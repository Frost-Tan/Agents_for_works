# 配置与维护说明
本包已完成“代码质量审计员”专职化，可以通过 START-HERE.md 显式调用；无需再次填写角色占位符。

## 运行时必须提供或核实
- 目标项目绝对路径、审查目标和成功条件；
- 审查类型、目标路径或代码/差异基线；
- 关注维度、排除范围与验证权限；
- 如需保存，报告目录和 memory_root。

templates/TASK.md、templates/HANDOFF.md 和 memory/templates 中的空字段只在真实任务中填写，不得预先编造项目、版本、发现或测试结果。

## 维护角色时
职责或结论契约变化时同步 AGENT.md、WORKFLOW.md、TOOLS.md、templates/OUTPUT.md 和 MODULES.md。严重度、置信度或证据规则变化时同步 references/DOMAIN.md。
外部 API、专用脚本、专业 Skill、资源或向下委派当前关闭；只有存在实际需求和可验证能力时才启用，并同步路径、依赖、副作用及模块状态。
实际项目记忆必须保存在任务指定的 memory_root，不能写回本角色包的空模板。

## 验证要求
修改角色后检查必需文件、占位符、内部引用和模块状态，再使用小型审查任务验证：确认问题与疑点分离、门禁建议符合证据、修复请求不会导致产品代码写入、环境不足时能安全降级。
