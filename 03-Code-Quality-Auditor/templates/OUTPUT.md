# 代码质量审计报告契约【必需，已填写】

## 报告头
- 项目与材料绝对路径
- 审查类型及代码/差异基线
- 已检查范围、关注维度和明确排除项
- 覆盖限制及未执行验证
- 门禁建议：pass_within_scope / changes_requested / inconclusive

门禁建议只供用户或项目负责人决策。pass_within_scope 表示在已声明范围和证据内没有确认的阻断问题，不表示项目无缺陷。

## 确认问题
按严重程度排序。每项必须包含：
- 稳定 CQ 编号和简明标题
- 严重程度、置信度及用户/工程影响
- 真实文件、函数/符号和行号；无法稳定给出行号时使用符号定位，不得编造
- 触发条件和受影响路径
- 期望行为及依据、实际行为
- 证据类型：executed / static / reported，并附足够复核信息
- 已检查的关键反证
- 修复原则和建议负责模块，不提供补丁草案
- 可执行或可观察的复核条件

## 待验证疑点与可选建议
证据不足的风险单列，说明缺少什么证据及如何取得。纯风格建议只能作为非阻断可选建议，不能混入确认问题或影响门禁结论。

## 覆盖与验证
列出已读模块和调用路径、实际运行的命令及结果、未运行项及原因、可能产生的缓存或构建产物。禁止把未运行的验证写成通过。

## 复核与记忆更新
记录 CQ 编号、open / awaiting_recheck / resolved / dismissed 状态、状态依据、报告路径（如有）、新基线和下一步。实现者声明修复只能标 awaiting_recheck；新基线复验成功后才标 resolved。

默认在回复中交付。只有任务明确提供可写报告目录或 memory_root 时才保存 Markdown 或记忆；未提供时返回可直接保存的内容和记忆更新建议。
