# 代码实现流程【必需，已填写】
1. 核实目标、验收、范围、兼容要求、读写授权和记忆。读取项目适用指令、技术栈、依赖与构建清单、相关入口、测试、文档及 Git 状态/差异，区分用户已有改动和本次基线。
2. 从现有调用链和契约确定最小完整实现面，包括相关源代码、测试、类型、配置、开发文档和构建脚本。能从项目发现的事实不询问；低风险假设须在交付中说明，高影响歧义先核实。
3. 在任务范围内实现代码和必要的小范围重构，保持现有架构、风格和兼容性。不覆盖、回滚或清理用户已有改动；发生重叠时先理解并融合，不能安全融合则停止相关部分。
4. 为新行为、缺陷复现和重要边界新增或更新测试。测试应验证可观察行为，不仅匹配实现细节；不为了让测试通过而削弱断言、隐藏错误或无关改动基线。
5. 运行从项目中确认的格式检查、类型检查、静态分析、针对性测试和必要的较宽回归测试。先识别副作用；外部系统优先使用替身或本地测试环境，真实服务、凭据、费用或生产数据须先获授权。
6. 检查最终差异是否仅包含预期文件，确认没有覆盖用户改动、泄露凭据、意外生成文件或未经批准的依赖/契约/迁移变化。对既有失败与本次回归分别归因。
7. 按 templates/OUTPUT.md 交付完成状态、行为变化、关键文件、验证命令与结果、未验证项、假设和剩余风险。高风险、跨模块、公共接口或数据兼容变更建议交独立质量审计员复核。

## 失败与停止条件
- 需求不完整：先完成不依赖缺失决定的调查或实现；只有高影响选择才停下核实。
- 工作区已有改动：保留并隔离，不回滚、不覆盖；能明确归因则继续，冲突或来源不明时报告受阻范围。
- 测试已有失败：记录基线证据，继续验证可隔离部分；不能区分是否由本次引入时不得声称验证通过。
- 工具或依赖缺失：不为普通实现擅自安装或升级；使用现有替代验证，说明缺口和建议命令。
- 需要新增生产依赖、破坏公共契约、迁移数据、连接真实外部系统或执行不可逆动作：提交方案、影响和回退条件，等待明确授权。
- 验证连续失败：分析根因并进行有界修复；相同原因反复出现或达到任务限制时交付 partial/blocked 和下一步，不无限重试。
