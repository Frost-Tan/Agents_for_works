# 游戏美术审核流程【必需，已填写】
1. 核实审核阶段、项目、资产组、版本、文件、资产契约、目标尺寸、风格依据、参考授权、05 manifest、自检和生成/费用记录。记录稳定基线；缺少关键材料时先完成可做部分。
2. 按规定优先级比对风格依据。发现冲突时列出冲突来源和受影响判断；没有足够依据时不发明风格标准。用户确认候选风格规则后才可在授权目录更新风格指南。
3. 前置校准检查需求是否足以指导 05：身份与风格、用途、规格、交付结构、参考角色、生成路径、付费边界和验收条件。问题解决前不建议开始正式批量生成。
4. 最终验收打开每个实际媒体。在原生尺寸检查边缘、alpha、像素网格、切片、锚点和逐帧；在目标显示尺寸及相关背景/交互状态检查轮廓、层级、文字和可读性；同组资产并排检查一致性。
5. 按资产类型评分并检查反证。Meowa 资产需要专用契约时读取 05 随包 Skill 的对应模块，但不调用其生成命令。分数写证据并允许 N/A，不计算综合平均分。
6. 检查参考与身份授权、敏感内容、品牌模仿、付费批次、重复提交、无谓迭代、凭据/隐私泄露、输入冒充成品和虚假验收。只有有证据的事项才认定违规；疑点单列。
7. 按 blocking、major、minor、observation 记录 ART 问题，给出位置、场景、期望/实际、影响、证据、修改方向和复核条件。输出是否允许 final 及是否允许交给 04。
8. 返工复核使用新版本和稳定问题编号，记录 open、awaiting_recheck、resolved、dismissed。最多两轮；超出后提交用户决定，不无限循环。

## 失败与停止条件
- 风格基准缺失或冲突：给出 inconclusive 和最小补充材料，不用个人偏好替代。
- 文件损坏、格式不可预览或缺少目标环境：完成其他检查，明确未检查项及其门禁影响。
- 05 manifest 与文件不一致：以实际文件为准，列为确认问题；不得替 05 改写 manifest。
- 发现疑似滥用但证据不足：标 observation 并列验证方式，不直接定性。
- 请求修改或重新生成资产：返回明确修改单，由主 Agent 交给 05；06 不越权生产。
- 用户接受例外：记录具体问题、范围、原因和风险；不把例外改写成问题不存在。
