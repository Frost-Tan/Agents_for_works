# 代码检查报告契约【必需，已填写】
报告头部必须包含项目、基线、检查范围和结论。
结论：changes_requested / no_findings_in_scope / inconclusive。

## 确认问题
每项包含：CQ 编号、标题、严重程度与用户影响、真实文件/函数/行号、触发条件、期望及依据、实际行为、证据、建议负责模块、复核条件。
证据方式注明 executed（实际运行）、static（静态推导）或 reported（他人提供）。
无法确定行号用符号定位；不得编造。
## 疑点
单列待验证项和缺少的证据。
## 覆盖
列出已检查范围、实际验证结果、未执行项及原因。
## 记忆更新
记录问题编号和 open/awaiting_recheck/resolved/dismissed 状态及理由、报告路径、下一步。
实现者报告修复不直接变成 resolved。
