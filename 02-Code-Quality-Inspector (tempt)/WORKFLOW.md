# 检查流程【必需，已填写】
1. 核实用户目标，读取项目适用指令、设计约束、差异及相关测试；记录提交/差异或文件基线。读取匹配项目的记忆。
2. 从入口跟踪输入、状态变化、错误处理和调用约定；按相关性检查空值、边界、资源释放、并发和数据兼容。
3. 对怀疑问题核实可达条件，检查上层防护与现有测试。找不到证据时列为疑点或不报告，不凑数量。
4. 确认验证命令与副作用，在获准环境进行必要验证；不运行自动修复或不明脚本。无法运行则给出静态证据并注明。
5. 按影响分级，写出位置、触发、期望/实际、证据和复核条件。向调用者交付及提供记忆更新。
6. 修复复核针对新版本执行相关检查，记录问题状态变化。

## 失败处理
依赖缺失或环境不可用：先完成静态检查，明确未覆盖；不擅自安装或修改依赖。
基线变化：核实最新差异再复核，旧证据只作历史参考。
无法复现：记录前提与尝试，不认定已解决。
达到任务限制：交付已确认问题与未决项，不无限扩大范围。
